# 青少年 AI 心理健康平台 —— 算法后端

> AIC 算法大赛参赛项目 · 后端算法模块

## 项目概述

本模块为青少年 AI 心理健康平台提供后端算法能力，采用 **四层架构**（感知 → 评估 → 干预 → 升级）配合公平性审计、隐私保护和联邦学习三大支撑体系，构建安全、可信、有效的智能心理健康服务。

## 三项创新的业务接入（2026-11-17）

前端统一入口为“AI 倾诉”（`/chat`）。三项能力合并在同一倾诉工作区：聊天旁的“陪伴与感知”面板包含图文理解、质量纠偏、持续陪伴；小屏通过聊天工具栏打开同一个面板。图文依据直接跟随当前打开对话的最新消息，不读取另一段最近对话来填充。切换能力或收起面板不会重建聊天与已挂载的支持活动，草稿保留。

聊天语音持续进入可编辑输入框：中间识别修订替换所属语音片段，用户手动修改的文字保留。点击发送即划分本轮语音边界，先冲刷不足 100ms 的尾音并定稿，再提交本轮文字；不关闭麦克风、摄像头、音频图或识别连接。之后的语音进入下一份草稿，不与上一轮定稿重复合并。若定稿超时，提交当时可见草稿并重连识别服务，设备持续采集，迟到的旧连接结果不会串入下一轮。麦克风按钮仅用于明确开启或关闭录音。核验：`node scripts/verify_voice_send.mjs` 与 `node server/node_modules/tsx/dist/cli.mjs scripts/verify_voice_draft.ts`。

聊天回复下的“查看本轮依据”和通话页的“本轮感知依据”可展开实际模态、专家权重、概念关系与质量记录。持续陪伴在同一页面管理开启/关闭、自评曲线、试用预测、建议和反馈，依据来自本人最近交流与自评，区别于当前对话的即时图文证据。最新消息仍为用户发言时显示等待回复，不把旧结果当新结果；历史消息没有元数据时不自动补算。旧 `/companion` 地址重定向到 AI 倾诉并打开对应面板，导航和搜索不再保留独立板块；疗愈空间保留回到倾诉管理陪伴的链接。`GET /api/innovation` 仍保留为已鉴权的只读状态接口。

聊天和通话共用 `_prepare_chat_turn`：普通支持轮次实际执行本地 Chinese-CLIP 编码及稀疏知识专家，结果写入回复的 `innovation` 元数据，再作为低权重措辞参考进入提示词。原有五类情绪、风险计算、审计和高危升级继续使用各自的原入口。高危轮次跳过附加专家，避免阻塞升级。

| 创新 | 业务入口 | 已接入行为 |
|---|---|---|
| 知识＋视觉语言编码＋MoE | 聊天/通话准备、感知服务 | 真实文本与三帧CLIP前向；原始摘要校验；按实际缺失掩码分派专家；保留知识出处、审核状态与路由权重 |
| 多模态预处理与纠偏 | 浏览器摄像头 → 算法像素检查 | 每轮最多三张224px JPEG缩略帧；检查时序、新鲜度、尺寸、曝光、对比度、清晰度和中心均匀遮挡；差画面退回文字参考；音频保持真实缺失 |
| 持续追踪与主动支持 | 本人理解状态、持续陪伴面板、后台Worker | 用户纠正/拒绝/暂停继续约束支持目标；正式文本参考不依赖研究令牌；按上海日历聚合本人自评并展示下一日EMA试用预测；已有同意、租约、安静时段、回执与关闭流程继续生效 |

摄像头关闭、离开前台、设备断开或读数过期时清空采样缓存。浏览器只在用户开启摄像头、画面有人脸、读数有效时附带缩略帧。Node在保存用户消息前剔除 `visualFrames`；算法响应只含概率、质量和路由摘要，原图不落库。页面开关提示已说明临时图文推理用途。

三张原始缩略帧与本机 CNN 表情摘要分开打包：即使表情模型仍在加载、不可用或其概率已过期，只要当前人脸检测新鲜、三帧有效，仍独立发送 `visualFrames` 进行质量检查，不伪造表情概率。聊天和通话在请求发出时通过 ref getter 读取最新在场状态，避免等待语音定稿后继续使用旧的 React 闭包。关闭、后台、无人脸或检测状态过期时仍不发送画面。核验：`node scripts/verify_visual_turn_send.mjs`（真实 MediaPipe、离线人像视频、实际 Python 像素质量检查；聊天与语音回复为夹具），`node server/node_modules/tsx/dist/cli.mjs scripts/verify_facial_turn_input.ts`。

质量纠偏面板用环形质量参考、曝光/对比度/清晰度采样帧分布与处理流程展示本轮记录。分项条表示未触发对应画质问题的帧占比，不是模型准确率；缺少分项时显示未记录。是否采用画面以本轮实际模态及退回标记为准，影子模式的辅助 MOS 低分不会被前端自行当作退回。记录随对话回复更新，不伪称实时评分。

面板首屏提供可播放、暂停、逐步点击的四步检查记录回放：接收画面 → 检查问题 → 调整参考 → 形成理解。问题证据取自实际记录的异常帧占比和原因，调整步骤展示画面质量系数、画面保留或停用，最后展示本轮最终专家权重。回放是对已记录决策的分步解释，不是实时运算日志或图像修复；没有记录纠偏前权重时不构造前后差值，没有本轮记录时禁用播放。

面板顶部另提供实时摄像头预览、实际亮度、人脸检测状态和 0–3 帧采样进度，开启摄像头后即有反馈，不必等对话回复。预览只消费已经开启的共享流，不额外申请设备、不保存或自动上传画面；完整质量结果仍在本轮回复后更新。没有检测到人脸时明确显示原因，不伪造采样进度。关闭或切换面板会卸载预览绑定，设备轨道仍由统一媒体管理器控制。

人脸检测的 JS/WASM 从已安装的 `@mediapipe/tasks-vision` 同版依赖打包，模型随 `client/public/models/face_landmarker.task` 本地提供（来源和摘要见同目录 NOTICE）。开启时并行准备设备与检测器，同页再次开启复用检测器；关闭仍立即释放设备，卸载时释放检测器。浏览器核验：`node scripts/verify_quality_startup.mjs`、`node scripts/verify_quality_visuals.mjs`。

实时模型使用 `artifacts/innovation_fusion` 中的第三轮 `sparse_knowledge` 工件，原始权重、知识和向量摘要记录在 `deployment.json`。采用这一工件是因为它有与实际摄像头输入匹配的完整编码契约；第十六/十七轮依赖LLM、辅助文本和多路视觉联合表征的复杂分类器仍保持离线，不能直接用512维CLIP替代它们的输入。第十七轮原始像素质量代理已经迁入业务模块；没有把离线分类成绩作为业务接入后的准确率。

知识文件的状态是 `user_attested`，保留原始节点背书，不冒称独立专家审核，也不把未证明的知识增益写成已验证效果。图文三类极性与项目五类情绪保持不同任务，不互相重映射。校准来自原数据来源；实时图文输入的校准与项目人群效果尚未验证。

短期预测采用第十七轮锁定的EMA配方（alpha=0.4）。项目1–10心情分上的迁移属于试用，界面明确说明效果尚未验证，不复用公开数据量表的临床或误差结论。每日先聚合，最多14个日历日，至少3个观测日；超过3日空档重新积累，当天无自评则不输出下一日预测。预测不决定危机等级或自动启动活动。

正常启动时默认加载以上能力，并预热共享CLIP以减少首轮等待：

```powershell
npm run dev:algorithm
```

部署到另一台机器时，需要本地匹配的CLIP编码器（默认 `D:/ai/models/encoders/chinese-clip-vit-base-patch16`），可设置 `ROUND3_VLM_ENCODER` 改变位置。重新安装模型工件可执行：

```powershell
& '<项目venv>/Scripts/python.exe' scripts/install_innovation_models.py --source '<原始sparse_knowledge目录>'
```

运行时选项：`INNOVATION_ENABLED=0` 关闭新增辅助推理；`INNOVATION_FUSION_ARTIFACT` 指定融合工件；`ROUND3_ENCODER_DEVICE` 默认为CPU；`SUPPORT_AGENT_MODEL_REFERENCE=0` 单独关闭持续陪伴的文本模型参考。更换编码器或工件后重启算法服务。`/api/v1/innovation/capabilities` 报告文件部署状态，单次结果的 `available/reason` 才表示该次推理是否成功；缺模型会降级并显式返回不可用，不填造概率。

复核入口：`tests/test_innovation_integration.py` 和 `tests/test_support_http.py` 验证像素、缺失、流式/非流式一致及高危优先；`scripts/verify_personal_forecast.ts` 验证日历与预测；`scripts/verify_innovation_bridge.ts` 执行真实Node/Python/模型调用；`scripts/verify_innovation_browser.mjs` 在独立Vite端口5187验证实际React组件和浏览器采样。运行记录位于仓库 `output/innovation-integration/`，均为自编工程探针，不是独立真人评测。

## 各模块职责说明

### 1. perception（感知层）

**核心职责**：多模态情绪信号的采集与融合

从文本聊天、语音通话、面部表情、键盘/眨眼等行为模式四个通道实时采集情绪信号，通过多模态融合模块输出统一的情绪向量，为上层评估提供数据基础。

### 2. assessment（评估层）

**核心职责**：心理状态的量化评估与风险预测

基于感知层的情绪向量，结合标准化心理量表（PHQ-9、GAD-7 等）进行自动评分，利用时序模型追踪情绪趋势，输出风险等级和结构化评估报告。

### 3. intervention（干预层）

**核心职责**：分层智能干预方案生成与执行

根据评估结果匹配干预策略：轻度情绪波动 → CBT 对话 / 苏格拉底式提问；中度风险 → 个性化干预方案；高危信号 → 危机干预话术 + 安全计划。

### 4. escalation（升级层）

**核心职责**：危机信号的实时监测与专业转介

当感知层或评估层检测到高危信号时，立即触发升级流程：危机检测 → 自伤评估 → 紧急联系人通知 → 匹配推荐咨询师 → 预约协调。

### 5. audit（公平性审计）

**核心职责**：确保算法决策的公平性与透明度

持续监控模型在不同年龄、性别、地区等群体间的表现差异，计算公平性指标，提供 SHAP/LIME 可解释性报告，确保对青少年群体的算法决策公正可信。

### 6. privacy（隐私架构）

**核心职责**：全链路数据隐私保护

针对未成年人心理健康数据的特殊性，提供 PII 自动识别与脱敏、细粒度知情同意管理、端到端加密存储，确保符合《个人信息保护法》和《未成年人保护法》。

### 7. federated（联邦学习）

**核心职责**：隐私保护下的分布式模型协同训练

支持多所学校/机构在不共享原始数据的前提下协同训练情绪识别模型，通过 FedAvg/FedProx 聚合策略和差分隐私技术，在保护隐私的同时持续提升模型性能。

### 8. shared（共享数据类）

**核心职责**：全局通用组件的统一管理

提供跨模块复用的 Pydantic 数据模型、配置管理、工具函数和异常定义，避免各模块重复定义基础组件。

## 快速启动

> ⚠️ **必须用项目自己的虚拟环境启动，端口是 `8001`。**
>
> 不要用 PATH 上的 `uvicorn`。算法服务的依赖（尤其 `sherpa-onnx`）通常只装在项目 venv 里，
> 而用错解释器的后果**很隐蔽**：服务照常启动、`/health` 照常 200，但 `/api/v1/asr/ws`
> 会直接 404，前端「语音输入」从此静默失效 —— 只有查 `/api/v1/asr/status` 才看得出原因。
> 本项目已经因此坏过两次。

推荐用仓库根目录的守卫脚本（启动前会校验解释器、依赖、端口）：

```bash
# 在仓库根目录
npm run dev:algorithm          # 等价于 node scripts/run-algorithm.mjs
npm run dev:algorithm:check    # 只做检查，不启动
```

手动启动（等价做法，解释器必须指向项目 venv）：

```bash
# 安装依赖（只需一次）
"<项目 venv>/Scripts/python.exe" -m pip install -r requirements.txt

# 启动服务（开发模式）
"<项目 venv>/Scripts/python.exe" -m uvicorn main:app --host 127.0.0.1 --port 8001

# 访问 API 文档
# http://localhost:8001/docs
```

启动后自检（`streaming_available` 必须是 `true`，否则语音输入不可用）：

```bash
curl http://localhost:8001/api/v1/asr/status
```

## 技术栈

| 类别 | 技术选型 |
|------|---------|
| Web 框架 | FastAPI |
| NLP | HuggingFace Transformers |
| 语音 | Librosa + MediaPipe |
| 视觉 | OpenCV + MediaPipe |
