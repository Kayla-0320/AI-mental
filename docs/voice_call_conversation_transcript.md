# 通话过程记录（每轮对话像文字对话一样可读）

> 用户口径（2026-10-11）：**"现在 AI 电话看不到完整的对话过程，我需要把每轮对话过程都像文字对话那样弄出来。"**

## 1. 用户看到的问题是什么

改之前，通话页中间那块是**两块扁平字符串数组**拼出来的字幕区（`useVoiceCall` 的
`userLines` / `aiLines`，页面上 `maxHeight: 38vh`）。它回答的是"现在屏幕上该显示什么字"，
回答不了"这一通电话聊了什么"：

| 现象 | 根因 |
| --- | --- |
| 分不清哪句是谁说的 | 没有讲话人字段，只能靠左右对齐去猜 |
| 读不出"这句话是第几秒说的" | 没有时刻 |
| 看不出轮次 | 两个数组各自追加，顺序是**写入顺序**，不是一条时间轴 |
| 流式回复看起来像"又冒出一句" | `aiLines` 的尾条被 `[...prev.slice(0,-1), full]` 反复整体改写 |
| "改稿过""没念出来"对不上账 | 事实散在别处（`revised` / `unspokenTail`），不挂在某一条消息上 |
| 翻不回去 | 只显示当前字幕，没有可滚动的历史 |

## 2. 改成什么

把"字幕"与"过程"**分成两件事**（字幕数组保持原样不动，避免改坏既有验证过的行为）：

```
        说话 / SSE / TTS 事件
                 │
      ┌──────────┴──────────┐
      ▼                     ▼
 userLines / aiLines     transcript（新）
 "现在显示什么字"          "聊了什么"：讲话人 + 时刻 + 轮次 + 全文
 （不动）                  （页面按轮铺开、可滚动回看）
```

* 数据模型与纯函数：`client/src/services/callTranscript.ts`
* 离线回归：`scripts/verify_call_transcript.ts`（8 组，不需要浏览器）
* 页面渲染：`client/src/pages/patient/VoiceCall.tsx`（`.vc-transcript-scroll` + `CallBubble`）

### 页面长什么样

* 顶栏不变（小安头像 + 状态词 + 开始通话键 + 计时），头像从 118px 收到 68px；
* 中间整块是**消息流**：每轮之间一条细分隔线，写着
  `第 N 轮 · 通话第 mm:ss · HH:mm:ss`；
* 两条气泡沿用文字对话页的语言（用户靠右紫底、小安靠左白底），每条气泡上方一行
  小字标出该条的相对时刻与真实时刻；
* 贴底时自动跟随新消息；用户往上翻看历史即**停止自动跟随**（阈值 48px），
  右下角出现「回到底部 ↓」；
* `?debug=1` 面板多了两格自检读数：`过程记录 = N 条 · M 轮`、`改稿/未朗读 = x / y`。

## 3. 数据模型

```ts
interface CallTranscriptEntry {
  id: string;            // 稳定 key，也是"替换尾部"的判据
  speaker: 'user' | 'ai';
  text: string;          // 全文（AI 那条可能被本轮后续增量整体改写）
  turn: number;          // 轮次：AI 的回复与其前一条用户消息同号
  tsMs: number;          // 写入时刻（墙钟）→ 页面减通话开始时刻 = "通话第几秒"
  revised?: boolean;     // 这一轮被安全审计改稿过
  unspoken?: boolean;    // 这一条里有一段没有被念出来（打断/改稿/危机/挂断）
}
```

三条写入口径（与 hook 里既有的 `setUserLines` / `setAiLines` **同源同刻**）：

| hook 里的写入点 | 时间轴上的动作 |
| --- | --- |
| `handleVoiceFinal`（用户定稿） / `endCall` 冲刷出的最后一句 | 新增一条用户消息，**并开启新的一轮** |
| `onSpeak` 计划 / 改稿 / 字幕随音频逐段揭示 / `flushSubtitleRemainder` | **替换**尾部那条 AI 消息（同一轮回复的后续增量） |
| `onDelta` 的纯文字路径（无音频） | **追加**到尾部那条 AI 消息 |

轮次号取自 `TurnAccumulator.turnId`（hook 里既有的对账编号，从 1 起）；
若该轮还没归属用户消息（异常路径），退化成"用户已开口数 + 1"，保证单调不串轮。

## 4. 安全边界（一个字都没变）

* **只做编排**：不改字、不删字、不截断。文本取的是既有 `setAiLines` 的**同一个字符串**
  （诊断改稿后的文本原样进来），所以"字幕最终等于模型全文"这条既有不变式不受影响。
* **不涉及风险**：不读写风险等级、融合权重、画像分数 —— 通话记录是旁路呈现。
* **不写库**：落库仍走原来的会话消息链路，本字段只在页面内存里。
* **只增不删**：断网重连、打断、改稿、危机切换都不会清空已说出的内容；
  只在**从 `idle` 进入通话**时清空一次（与顶栏计时同一口径，`connecting → error → 重试`
  不会清掉用户已经看到的过程）。
* 「未朗读」的标注口径不变：字照样上屏，但明确标出这一截没有出声 ——
  过程记录里对应那条消息也带同一条标注（`CallBubble`）。

## 5. 怎么验证

```bash
# 1) 离线回归（纯函数，8 组：交错 / 改稿 / 打断 / 长通话 / 时间戳单调 / 退化路径）
node "server/node_modules/tsx/dist/cli.mjs" scripts/verify_call_transcript.ts

# 2) 类型与生产构建
cd client && npm run build
```

真机走查（`?debug=1` 打开诊断面板）：

1. 打一通 3 轮以上的电话 → 消息流里应出现 3 组，每组一问一答，轮次与时刻递增；
2. 中途打断一次 → 被掐断的那条 AI 消息下端出现「这一截没有说话」；
3. 触发一次审计改稿 → 该条标注「安全审计已改稿」，且**没有**变成两条；
4. 往上翻历史 → 新消息不再把视图拽回底部，右下角出现「回到底部 ↓」；
5. 面板核对 `过程记录` 条数 = 屏幕上气泡数（含正在流式的那条）。

## 6. 已知取舍

* 正在流式的回复会**同屏出现两次**（消息流里逐段长高的那条 + 下方浅色斜体的
  `partialText` 之间是两回事：前者是 AI 的，后者是**用户**边说边出字）。AI 那条在
  流式期间自身只有一份，随音频逐段揭示；这是"字幕与声音同步"的既有取舍，没有改。
* 消息流不做虚拟滚动：一通电话的轮次量级（几十条）不需要它；
  若将来出现超长通话，再按 `transcript.length` 上虚拟列表。
