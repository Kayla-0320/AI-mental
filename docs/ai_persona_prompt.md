> **来源**：用户 2026-10-11 给出的《角色设定：温暖、真诚的心理陪伴伙伴》草稿。
> **落点**：`algorithm/api/intervention.py::_build_llm_messages` —— 全仓**唯一**一处
> 主提示词（`grep "AI 陪伴者"` 只有这一处，前端/服务端都没有第二份）。

## 0. 本版（2026-10-11 第二次改版，**以用户草稿为准**）

用户把整段提示词换成了自己写的七条对话原则（自然真诚 / 简洁适度 / 先倾听再引导 /
适时提问 / 尊重 / 适合语音交流 / 保持合理边界）+ 对话目标，原话：
**"而且这最后一句回复明显不对啊，提示词我觉得可以少点，改成这个试试"**。

截图里的"不对"是这一句：ta 只说半句「**我说。**」，AI 回「**我在听。**」——
一句表态，什么内容都没接住。用户判断这是"回复明显不对"，而不是"太短"。

| | 上一版（v2，2287 字） | 本版（v3，**1829 字**） |
|---|---|---|
| 主体 | 自写：怎么说话 9 条 + 按情况回应 7 条 + 说之前先想 + 不许做 + 底线 | **用户草稿**：角色设定 + 对话原则 7 条 + 对话目标 |
| 「按情况回应」 | 有（七种情境逐条给打法） | **删**（与七条原则重复，且条数一多模型会把回复压到最保险的形状） |
| 「说之前先想」 | 有（先判断再动笔） | **删**（同上） |
| 敷衍式短回复 | 无判据（只要求"短"） | **有**：「只表个态、什么内容都没接住的短回复，等于没回应」+「ta 的话**明显没说完**（只剩半句、话头断在那儿）时……先把话头接住（用你说出来的方向，只许用 ta 说过的内容，细节不许补），再请 ta 接着说」 |
| 提问 | 选项（优先级 倾听 > 建议 > 引导） | 选项（草稿第 4 条，含义相同） |
| 身份 / 格式长度 / 不许做 / 底线 | 有 | **原样保留**（机器与安全上必须的那三块，见 §3） |

**为什么"少点"不是审美偏好**：v2 把"分档提问优先级 + 按情况回应 + 说之前先想 +
禁用清单"全塞进 prompt，约束条数一多，模型为了同时满足它们会把回复压到最保守的形状上
—— 「我在听。」就是被压出来的形状之一。本版减少约束**条数**，把长度交给分档上限
（代码同源，见 §3 第 3 条）。

**本版新增的回归测试**（`algorithm/tests/test_intervention_prompt.py::TestPersonaDraft`）：

| 测试 | 盯的是什么 |
|---|---|
| `test_persona_is_the_users_draft` | 草稿本体在 prompt 里：标题 + 七条原则标题 + 对话目标（防止有人"顺手重写"草稿） |
| `test_content_free_short_reply_is_forbidden_abstractly` | 敷衍式短回复的**抽象**判据在，且「我在听」这句**不在** prompt 里（念一遍就是提示一次） |
| `test_verbose_sections_are_gone` | 「按情况回应」「说之前先想」两节确已删除 —— 这是"少点"的闸门 |
| `test_safety_and_identity_survive_the_rewrite` | 改草稿不得动身份与安全红线（AGENTS.md） |

`test_prompt_is_compact` 的上限随之由 2400 收紧到 **2000**（实测基线 1829：
草稿本体 1778 字 + 针对"半句"补的那 51 字）。

### 0.1 真机验证（2026-10-11 15:2x，重启 8001 之后，`fallback=false` 证明真的调了千问）

```powershell
# 探针直接打本地算法服务（--port 8001），prompt 由服务进程加载
POST /api/v1/intervention/smart-chat  {user_id, message, conversation_history}
```

| 输入 | risk | 回复 | 判定 |
|---|---|---|---|
| **截图那条**：「我说。」+ 截图里那几轮历史 | medium | 「我在听，你说。」(**7 字**) | ⚠️ **仍然偏空**（见下） |
| 「我说。」（空历史） | medium | 「嗯，我在听呢～你慢慢说，我在这儿陪着。」(19 字) | ⚠️ 套话，但比上一条完整 |
| 「我这次数学只考了六十多分，感觉自己白学了。」 | medium | 「六十多分，确实挺让人沮丧的……感觉白学了，说明你其实很认真在学，只是这次没看到想要的结果。想聊聊这次考试，或者最近学习时遇到的卡点吗？」(67 字) | ✅ 接住内容 + 一个问句 |
| 「我感觉好些了，谢谢你陪我聊」 | low | 收束四步（承接 → 复述 → 小提醒 → 留门），100 字正好在硬上限 | ✅ 无"你已经好了"，无幻觉 |
| 「我现在不想说这个。」 | medium | 「嗯，好，那咱们就不说这个。你随时想聊什么，或者什么都不想聊，都行。」(33 字) | ✅ 尊重拒绝、不追问 |

**诚实结论**：本版提示词把普通情绪轮、拒绝轮、收束轮都改好了，但**没有修掉截图那条** ——
「我在听，你说。」仍是"只在表态"。两次尝试（初版判据 / 收窄成"明显没说完"的判据）
都没能改变这一条，说明模型对"两三个字的半句输入"有很强的先验。

两条后续路线（**需要人定**，不要同时上）：

1. **确定性兜底（代码层）**：定稿侧加判据"非危机、非收束轮的回复 < N 字且不含问句
   ⇒ 追加一句指令重问一次（`_call_llm` 只多一次调用，仅在这一种情况下发生）"。
   好处是不依赖模型自觉、可离线测；代价是这条路径多约 1 次 LLM 延迟（~0.5–1.2 s）。
2. **先修输入侧**：截图里的「我说。」本来就更像**半句被 ASR 判停切掉**（ta 后面还有话），
   这属于已排期的 ASR 端点实验（rule1/rule2 由 1.8 s 逐档降到 1.2 / 1.0，
   见 [voice_call_interrupt_tuning.md](voice_call_interrupt_tuning.md)）——
   输入完整了，"接不接得住"就不再是这一条的问题。

## 1. 上一版（v2）改了什么（历史，保留）

把**提问从"每轮必问"降级为"选项"**，并写明优先级：

**倾听 > 建议 > 引导性提问**（用户原话："当用户只想倾诉时，倾听优先于建议；
当用户需要具体帮助时，给出简短建议；当用户的表达需要进一步了解时，再提出一个引导性问题"）。
这一条的语义在 v3 里由草稿第 4 条承接，**没有变化**。

| | 旧版（2026-10-05 ~ 10-11） | 新版 |
|---|---|---|
| 提问 | **每一轮**最后一句**必须**是一个关心 ta 的问题 | **先接住，再决定要不要问**；只想倾诉时可以一个问题都不问 |
| 形状 | 第一句陈述 + **只有**最后一句是问句 | 第一句必须是陈述；**要问**就问在最后一句，没问题 |
| 收尾套话 | 每轮都以问句收尾（实测退化成「你觉得呢？」「你愿意多说一点吗？」） | 这两种空话被**点名禁止**（"只求一个『嗯』的空话"） |
| 回应策略 | 散落在各处 | 新增「按情况回应」一节（**v3 已删**，见 §0） |
| 想清楚再答 | 无 | 新增「说之前先想一遍」（**v3 已删**，见 §0） |
| 依赖关系 | 提问是默认动作 | 提问是**判断结果**；拒绝深谈、情绪未平复、好转收束、高风险一律不问 |

**为什么必须改**：用户反馈"AI 每次都用『你觉得呢？』或『你愿意多说一点吗？』结尾，
听起来像机械地执行话术"。旧契约（每轮必须有问句）在提示词层面就把这句套话逼出来了 ——
不是模型偷懒，是契约要求的动作只有这一个能做。

## 2. 与用户草稿的**刻意偏离**（都可回退，先说清楚）

v3 几乎逐字采用用户草稿，只做下面这几处偏离（每处都有硬理由）：

| # | 草稿写法 | 落地写法 | 为什么 |
|---|---|---|---|
| 1 | 给出示范问句：「这件事里，最让你难受的是什么？」「你愿意和我多说一点吗？」「你现在更希望有人听你说说，还是一起想想办法？」 | **不写示范句**，只写判据（"能不能真帮 ta 说清楚、更靠近 ta 在意的事"） | 2026-10-05 的事故：prompt 里的示范台词被模型**整句照抄**，实测连续四轮同一句开场，用户当时反馈"每次回复都是一样的话术"。示范句在 prompt 里等于反复提示 —— 而且这三句里有两句正是用户这次抱怨的套话本身。`test_prompt_carries_no_copyable_example_dialogue` 现在盯着这条 |
| 2 | 通用"温暖、真诚的心理陪伴伙伴" | 保留「**心灵花园**」+ **青少年** + "不能替代线下持证的心理咨询师与精神科医生" | 产品身份与合规表述已在用（前端标题、免责声明、AGENTS.md 安全红线）；草稿 §4 的边界与它同义，已合并而非丢弃 |
| 3 | "1～3 句，原则上 30～100 个汉字" | 30~100 字照收，但**保留分档硬上限**：一般闲聊 **40 字**、其余 **100 字**（`_MAX_REPLY_CHARS` / `_MAX_SOCIAL_REPLY_CHARS`） | 100 字是客户端 TTS 单段合成上限（`MAX_TTS_UNIT_CHARS=100`）与既有用户要求；闲聊 40 字是 2026-10-05 用户明确要求"一般闲聊 40 字以内就够了"。语音通话里超长会被切成多段播报 |
| 4 | 草稿没有"敷衍式短回复"这一条（v3 草稿第 2 条只说"不要为了简短而显得敷衍"） | 补一句**可执行的判据**：「只表个态、什么内容都没接住的短回复，等于没回应；哪怕 ta 只说了半句，也要把那半句接住，或者把没听清的地方问清楚」 | 用户这次的问题就是截图里那句「我在听。」。草稿原话太软（"显得敷衍"是主观的），判据必须能对上具体动作。⚠️ 反面示范（「我在听」本身）**不写进 prompt** —— 2026-10-05 的教训是写进去就会被照抄 |
| 5 | 草稿只有第 7 条一句边界（不诊断 / 不夸大 / 不制造依赖） | 补齐三块：**身份**（「心灵花园」+ AI 陪伴者 + "不能替代线下持证的心理咨询师与精神科医生"）、**格式与长度**、**不许做 + 底线** | 前两块是产品与合规要求（前端标题、免责声明、AGENTS.md）；底线是安全红线，**危机轮必须做安全确认并给热线**，草稿那句"引导其及时寻求现实中的专业帮助"没有可执行落点 |

## 3. 保留的硬约束（都有来源，别当冗余删）

1. **第一句必须是陈述** —— 语音首声天然落在共情反映上，是"已经播出去的第一句"
   最安全的一种（见 [voice_call_research.md](voice_call_research.md) §首句缓冲）。
2. **一次最多问一个** + **要问就问在最后一句** —— 口语轮次里 ta 才知道轮到自己说了。
3. **绝不超过 100 字**（闲聊 40 字）—— 与客户端分段合成上限同源。
4. **不许说 ta 没讲过的事** —— 截图事故"用户只说『你好』，AI 回『你今天看起来有点没精神啊？』"。
5. **禁诊断 / 禁药物 / 禁否定感受**（「想开一点」「很多人比你更惨」）—— AGENTS.md 安全红线。
6. **底线（危机）**：先确认 ta 此刻是否安全、有没有立即危险 → 联系身边信任的大人 /
   心理危机热线 / 医院心理科；**这一轮的安全确认不受"提问可选"影响，必须问到**。

## 6. 真机实测（2026-10-11 14:2x，重启 8001 之后）

`POST /api/v1/intervention/smart-chat`（`fallback=false` 证明真的调了千问，即新提示词在生效）：

| 输入 | risk | 以问句收尾 | 回复 |
|---|---|---|---|
| 今天在学校跟同桌闹别扭了，心里挺堵的，不想跟人说话 | medium | 是 | 「嗯…闹别扭了，心里堵着，连话都不想说——这感觉挺真实的。你愿意说说，当时发生了什么吗？」(43 字) |
| 我一到考试前就睡不着，有什么办法吗 | medium | 是 | 「嗯，考试前睡不着，整个人都绷着…你愿意说说，是担心考不好，还是身体特别清醒、怎么也放松不下来？」(69 字) |
| **我今天就是有点累，想跟你说说，你不用给我建议** | medium | **否** | 「嗯，听到了，今天就是有点累……想说的时候就在这儿说，我听着呢。」(31 字) |
| **我感觉好些了，谢谢你陪我聊** | low | **否** | 收束四步：承接 → 复述 → 小提醒 → 留门（100 字，正好在硬上限） |
| 嗯，我在听 | medium | **否** | 「嗯，我在这儿听着呢～ 你愿意开口，就已经是很重要的一步了。」(31 字) |

* **"只想倾诉就不问"真的能触发**（第 3 行）—— 这是旧契约下不可能出现的一轮。
* **收束轮不问问题**（第 4 行），且没有"你已经好了"这类断言。
* 顺手抓到一个**真机才暴露的缺陷**（第 4 行那次回复）：模型编造了 ta 从没说过的话
  （「刚才你说试着把心里的话说出来……还提到今天早饭吃得很慢，也没催自己」）。
  根因是收束第 2 步**索要**"复述 ta 说过的内容"，没有素材时模型就去编 ——
  **光在提示词里加"不许编"压不住**：加完再测两轮，仍然编出
  「刚才你提到，试着把心里的话说出来」「刚才你提到想先安静一会儿，也愿意试着把
  烦心事写下来」。
  最终改成**结构性约束**：新增 :func:`_quotable_user_lines`，把**允许复述的用户原话
  逐条列进 prompt**（最多最近 3 句、去重、滤掉「嗯/好」这类应声）；一句都没有时
  明示"跳过第 2 步"。模型两种情况下都没有"凭空写"的余地。

  **修后真机验收**（同一台机，重启后）：

  | 场景 | 回复 | 判定 |
  |---|---|---|
