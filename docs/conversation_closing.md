# 收束轮（结束对话的语言）：判据、话术与安全边界

> 用户需求（2026-10-11 原话）：
> **"当用户说'我感觉好些了'，就可以不用再问问题了，可以说一些结束对话的语言。"**
>
> 实现落在算法层（`algorithm/api/intervention.py`），**前端无需改动** ——
> 收束轮的回复照样走既有的 SSE/字幕/TTS 链路。聊天页与通话页同时生效，
> 因为两条路径共用同一个 `_ask_question_this_turn`（两个调用点，见 §4）。

---

## 1. 做什么、不做什么

| 做 | 不做 |
|---|---|
| 本轮**不再提新问题**（结尾不出现问号） | ❌ **不自动挂断通话**。"要结束会话"是用户自己的事，AI 只负责把话说完 |
| 说一段**收束语**：克制承接 → 复述这次谈话里对 ta 有用的一两点 → 一句可带走的小提醒 → **留门** | ❌ 不说"你已经完全好了 / 你没事了 / 你治好了" —— 好转是 ta 的感受，不是 AI 的结论（禁止诊断性语言，见 AGENTS.md 安全红线） |
| 只影响**这一轮**；用户继续说别的事，下一轮恢复正常节奏 | ❌ 不写库、不改风险等级、不触发升级流程的任何变更 |

---

## 2. 判据（纯词面匹配，不调模型）

`_closing_intent(user_message, risk_level) -> 'improved' | 'ending' | None`

判定顺序（每一步都有理由，写在代码注释里）：

```
① risk_level ∈ {high, crisis}            → None   ← 安全优先，见 §3
② 同一句里出现危机词（_detect_crisis）      → None   ← "我好多了，但有时候还是想死"
③ 明确的结束意图                          → 'ending'
④ 否定 / 未好转表达                       → None   ← "我不好" "我不好受" "我没好"
⑤ 好转表达                                → 'improved'
   ⑤a 转折词之后仍压着负性词（"我好多了，但还是有点担心"）→ None
   ⑤b 同时带道谢用语（"谢谢你，我好多了"）           → 'ending'
```

* **好转**：`我好多了`、`我感觉好些了`、`没那么难受了`、`心里舒服多了`、`想通了`、
  `我明白了`、`我知道怎么做了` …（36 条完整短语，**刻意不收单字"好"** —— "好的"是应声）
* **结束**：`我先不聊了`、`先这样吧`、`下次再聊`、`我要去忙了`、`去写作业`、
  `拜拜`、`再见`、`先挂了` …（19 条）
* **刻意不收**：单独的"谢谢"（正常寒暄，道完谢往往还想说）、单独的"挂了"
  （青少年口语里"我挂了"更常是**考砸了**，判成想结束会把一场考试失利的谈话直接收尾）、
  单字"好"。
* **主语守卫**：不带主语的短表达（"好多了"）要看过它**最近的主语标记** ——
  `我朋友好多了` / `她好多了` → 不是 ta 自己；`妈妈，我好多了` → 仍是 ta 自己。

## 3. 安全边界（这条比功能本身重要）

1. **高风险/危机一律不判收束** —— 哪怕 ta 刚说"我好多了"。
   危机过后的"我好多了"恰恰是最需要核实的一句，此时必须继续走安全确认与转介。
2. **同一句里带危机词也不判** —— 复用本文件唯一的危机词表 `_detect_crisis`，
   不另建第二份（两份词表必然漂移）。代价是 `累了` 这类宽泛词会造成**漏判**
   （"没那么累了"判不出来）：漏一次收束只是多问一句，错一次收束是**提前把求助的门关上**。
3. **降级路径没有收束语**（已知缺口）：未配置 `DASHSCOPE_API_KEY` 时走模板回复
   `_generate_empathy_reply`，它只会按 `ask_question=False` 取"不含问句的陪伴话术"，
   **不会说结束语**。要覆盖无 key 的演示，需要另写一组收束模板 ——
   那是新话术，按 AGENTS.md「安全相关变更需人工审核」留给人工定稿，这里**不擅自编写**。
4. **危机词表覆盖不到的告别式危机**（例如"我已经站在楼顶了，再见了"）仍依赖上游
   `risk_level`。收束判据复用了既有词表，此处风险与改造前等同；
   建议在上游严重度判定侧另行加固 —— 不在本次改动范围内。

## 4. 接线（互斥链）

prompt 侧（`_build_llm_messages`）有三条"本轮附加规则"，按
**收束 > 寒暄 > 不提问**排成互斥链，**任一轮最多只有一条生效**：

```python
closing_intent = _closing_intent(user_message, risk_level)

if closing_intent:          social_line = ""          # 否则与"邀请 ta 开口"的寒暄打法直接打架
elif 已问过好 / social_only: social_line = "..."

if closing_intent:          no_question_line = ""      # 由头和打法都在 closing_line 里
elif not ask_question ...:  no_question_line = "..."
```

* 为什么不并存：收束轮要求"结尾不要出现问号"，寒暄轮则**建议**"想邀请 ta 开口就轻轻问一句"；
  实测同一段 prompt 里既让问又不让问时，模型会挑更显眼的那条（通常还是问），**收束静默失效**。
* `no_question_line` 的结论虽然一样（别问），但它的由头是"ta 不想谈 / 情绪没平复"，
  会把收束带偏成安抚，把"复述 + 小提醒 + 留门"整段丢掉。
* **不做**新增开关：收束轮天然是"不许提问"的一轮，定稿侧既有的
  `_strip_trailing_question` 兜底删尾问句，不变量继续成立。
* ⚠️ **2026-10-11 起基础提示词已改版**（提问从"每轮必问"降级为选项，见
  [ai_persona_prompt.md](ai_persona_prompt.md)）：收束轮不再是"某个总则的例外"，
  它本身就是"这一轮不问"的一种；上面这条互斥链与判据**一个字都没动**。

收束指令本身（prompt 里那段 `closing_line`）四步：

```
1. 克制承接（"听你这么说我挺高兴" / "这段时间你做了不少努力"）
   ⚠️ 禁语：你已经完全好了 / 你没事了 / 你治好了
2. 复述这次谈话里对 ta 有用的一两点（只复述，不讲道理、不列清单）
   ⚠️ 复述源是**白名单**，由代码生成（`_quotable_user_lines`）：把 ta 自己说过的
   最近 ≤3 句原话逐条列进 prompt，模型只能从里面挑；一句都挑不出（历史里没有实质
   内容）时明确"跳过这一步"。
3. 一句能带走的小提醒（通用的小办法，具体、轻一点，别写成医嘱；同样不许挂在 ta 没说过的事上）
4. 留门（"之后需要我，随时都在"）—— 放在最后，后面不再补内容
```

> **为什么第 2 步要白名单（2026-10-11 真机回归）**：只在提示词里写"不许编"压不住。
> 实测（空历史 + "我感觉好些了，谢谢你陪我聊"）模型编出了
> 「刚才你提到，试着把心里的话说出来」「还提到今天早饭吃得很慢，也没催自己」——
> ta 一个字都没说过。根因是"复述"这一步本身就在**索要**"ta 说过什么"，
> 没素材时它只能编。加了禁令后连测两轮仍然照编，于是改成结构性约束：
> 把可复述的原话列出来，没有就不给这一步。修后同场景复测 2/2 干净，
> 有历史时只引用真实原话（`TestQuotableUserLines` 5 例 +
> `TestClosingPrompt` 2 例守住）。

已量过的一手结果（本机，2026-10-11）：

| 输入 | risk | 判定 | prompt 里的本轮规则 |
|---|---|---|---|
| 我感觉好些了 | low | `improved` | 收束轮（无寒暄邀请、无"不要提问"） |
