二、文本情感分类模型 — RoBERTa 微调

P0 最高优先级 模型信息

  • 模型文件：perception/text_emotion/model.py → train.py
  • 基座模型：hfl/chinese-roberta-wwm-ext（中文 RoBERTa）
  • 分类类别：5 类 — anxiety(焦虑) / depression(抑郁) / anger(愤怒) / neutral(中性) / positive(积极)
  • 数据格式：[{"text": "文本内容", "label": "anxiety"}, ...]
  • 当前状态：假数据 420 条（模板变体生成），需替换为真实标注数据
  • 最低数据量：每类 500+ 条（共 2500+），推荐每类 2000+（共 10000+）

推荐数据集

数据集名称 来源 规模 语言 适配方式
DepressionDataset (thu-coai) 清华大学 CoAI 组 / 微博 ~7000+ 帖子 中文 抑郁/正常二分类 → 映射到 depression 类，配合其他数据补充其余 4 类
Emotion (Elvis/sentiment) HuggingFace / 英文翻译 ~2000 条 英文 含 sadness/joy/anger/fear 等 → 需机器翻译为中文后使用
天池心理健康数据集 阿里云天池竞赛 ~10000+ 条 中文 心理咨询文本 → 可直接标注 5 类情感
中文社交媒体情感数据 学术论文 / 微博 规模不等 中文 微博情绪分类数据（WEIBO）→ 映射 anger/anxiety 等类别
Ren-CECps 情感语料库 大连理工 / 人民日报 ~35000 条 中文 含 8 种情绪 → 合并映射到 5 类体系
Mental Health Counseling 心理咨询对话 ~3000 对话 英文 翻译后用于增强 depression/anxiety 类样本
自建标注数据（推荐） 平台咨询记录 按需 中文 对平台真实咨询文本进行人工标注，最贴合目标域
关键适配要点 项目标签体系为 anxiety / depression / anger / neutral / positive，多数公开数据集的标签体系不同，需要建立映射表。例如：将 ISEAR 的 "fear" 映射到 "anxiety"，将 "guilt/shame" 映射到 "depression"。中性/积极类可从日常对话语料中采样平衡。

标签映射建议

fear / fear-panic → anxiety  |  sadness / grief → depression  |  anger / rage → anger  |  neutral / surprise → neutral  |  joy / love / gratitude → positive

训练命令

# 准备真实数据 JSON 文件（格式同假数据） # data/real_train.json: [{"text": "...", "label": "anxiety"}, ...] # 启动训练 cd algorithm python -m perception.text_emotion.train --data perception/text_emotion/data/real_train.json # 模型将保存至 perception/text_emotion/outputs/model/

三、多任务风险分级模型 — MLP 训练

P0 最高优先级 模型信息

  • 模型文件：assessment/multi_task/model.py → train.py
  • 架构：共享编码器(2层MLP) + 三个任务头(depression/anxiety/sleep)
  • 输入特征：20 维向量（感知层输出融合特征）
  • 输出：三个二分类概率（抑郁/焦虑/睡眠风险）
  • 数据格式：{"samples": [{"features": [...20维...], "depression": 0/1, "anxiety": 0/1, "sleep": 0/1}]}
  • 当前状态：假数据 1000 条，需替换为真实临床/筛查数据
  • 最低数据量：2000+ 条，推荐 5000+ 条

推荐数据集

数据集名称 来源 内容 适配方式
PHQ-9 抑郁筛查数据 临床量表 / 医院 PHQ-9 量表评分 + 人口统计 PHQ-9 ≥ 10 → depression=1；提取特征维度作为输入
DASS-21 数据集 (Kaggle) DASS-21 量表 / 社区 抑郁-焦虑-压力三维度评分 直接对应 depression/anxiety 标签，睡眠可从相关条目推导
PSQI 匹兹堡睡眠质量指数数据 临床睡眠研究 睡眠质量评分 + 相关指标 PSQI > 5 → sleep=1；与 DASS-21 联合使用获得三标签
HuggingFace 心理健康数据集合集 多来源 各类心理健康问卷数据 提取量表分数 → 二值化为三任务标签
平台自有数据（最佳） 平台用户心理档案 用户填写的 PHQ-9/GAD-7/PSQI + 多模态感知特征 直接使用感知层输出作为 features，量表分数作为标签
特征工程要点 该模型的 20 维输入特征应来自感知层的融合输出，包括：文本情感 5 维概率 + 语音风险分 + 面部风险分 + 行为风险分 + 键盘动力学特征 + 会话统计特征。如果使用真实量表数据训练，需要先从量表文本中提取对应特征，或使用感知层对量表文本进行推理后获取特征向量。
量表数据 → 感知层特征提取 → 20维特征向量 → 多任务模型训练 → 抑郁/焦虑/睡眠 三头预测

四、对抗去偏见模型 — GRL 对抗训练

P1 高优先级 模型信息

  • 模型文件：perception/text_emotion/adversarial_debias.py
  • 架构：RoBERTa 共享编码器 + 主分类头(情感) + 对抗分类头(GRL→敏感属性)
  • 需求：文本 + 情感标签 + 敏感属性标签（性别/方言/年龄组）
  • 数据格式：{"input_ids": ..., "attention_mask": ..., "label": 情感ID, "sensitive_label": 敏感属性ID}
  • 目标：情感分类准确率不降的同时，模型无法从特征中预测敏感属性

推荐数据集

数据集 说明 适配方式
性别偏见文本数据集 含性别标注的文本情感数据 情感标签 → label，性别 → sensitive_label
自建标注数据 在文本情感分类数据基础上，额外标注性别/年龄段/地域 最灵活，可精确控制偏见模式
微博抑郁数据集 + 性别标注 微博帖子含用户性别信息 文本→情感标注，用户性别→sensitive_label
核心要点 对抗去偏见需要同一批数据同时具有「情感标签」和「敏感属性标签」。最实用的做法是在文本情感分类数据（模块二）的基础上，额外标注每条数据的作者性别/年龄段/地域信息。建议至少标注性别（男/女/未知）三组，每组样本量均衡。

五、SProp GNN 语义盲图网络

P1 高优先级 模型信息

  • 模型文件：perception/text_emotion/sprop_gnn.py
  • 架构：语义图构建(词/句节点) → 3层GCN消息传递 → 对抗去偏见(GRL) + SProp正则
  • 需求：与对抗去偏见相同 — 文本 + 情感标签 + 受保护属性
  • 特色：图结构输入，对文本语义关系建模更强

数据需求

与对抗去偏见模型（模块四）共享同一数据集。额外优势：GNN 的图结构输入可以利用文本的词-句关系，因此长文本数据（如咨询对话、日记）对此模型效果更好。

数据复用建议 SProp GNN 与对抗去偏见模型可以共享同一份标注数据，一次标注同时训练两个去偏见模型，对比效果。

六、多模态融合 Stacking 元学习器

P1 高优先级 模型信息

  • 模型文件：perception/fusion/fusion.py → StackingFusion 类
  • 架构：LogisticRegression 元学习器，输入为文本+语音概率拼接的 10 维特征
  • 训练方式：fit(text_probs, audio_probs, labels)
  • 需求：各模态的概率输出 + 真实情绪标签

数据获取策略

Stacking 元学习器的训练数据需要分两步获取：

Step 1: 收集多模态数据 → Step 2: 用已训练好的单模态模型推理 → Step 3: 拼接概率 + 真实标签 → Step 4: 训练 StackingFusion

推荐数据源

数据集 说明 用途
IEMOCAP 情感数据库 英文对话情感（音频+文本+标签） 同时有文本和语音，可分别输入两个模型获取概率
CH-SIMS 中文多模态情感 中文多模态情感（视频+音频+文本） 最匹配！中文 + 多模态 + 情感标注
CMU-MOSEI / CMU-MOSI 英文多模态情感分析基准 翻译后可用，文本+音频+情感标签齐全
平台咨询录音+文本 语音咨询的录音和转写文本 最贴合实际使用场景

七、语音情感模型 — 声学特征分类

P2 中优先级 模型信息

  • 模型文件：perception/voice/acoustic.py
  • 当前状态：基于规则的经验映射（Scherer 2003 声学标志物）
  • 可升级方向：用标注数据训练 SVM/MLP 替换规则引擎
  • 特征：F0/能量/语速/停顿/共振峰/Jitter/Shimmer 等 12 维声学特征

推荐数据集

数据集 规模 语言 适配方式
IEMOCAP ~12h / 10039 utterance 英文 提取声学特征 → 训练分类器替换规则引擎
AISHELL-3 情感语音 85 小时 中文 中文情感语音，提取声学特征训练
EMO-DB (Berlin) 800 utterances / 7 emotions 德文 经典情感语音基准，验证特征提取pipeline
CASME / CAVE 中文情感语音 规模不等 中文 最贴合目标场景

八、联邦学习风险分类器

P2 中优先级 模型信息

  • 模型文件：federated/server.py + federated/client.py
  • 架构：LogisticRegression + FedAvg 聚合
  • 需求：多个「客户端」各自持有本地数据 + 风险标签
  • 当前状态：模拟 2 客户端，假数据各 500 条

数据获取策略

联邦学习的核心价值在于多机构数据不共享的前提下联合训练。推荐数据源：

  • 多所学校/医院的心理健康筛查数据 — 每个机构作为一个客户端
  • DASS-21 / PHQ-9 公开数据 — 按地域/机构拆分为多个客户端
  • 平台多地区用户数据 — 按地区自然划分客户端
实际部署建议 联邦学习在真实场景中需要各机构配合部署客户端节点。建议先使用公开数据集的分区版本验证流程，再逐步接入真实机构数据。

十、数据格式规范与接入方式

1. 文本情感分类数据格式

// 在 EmotionDataset 基础上增加 sensitive_label 字段 [ { "text": "我最近压力很大", "label": "anxiety", "sensitive_label": 0 // 0=女, 1=男, 2=其他 } ]

十一、伦理合规与数据安全保障

青少年心理健康数据的特殊伦理要求 本项目面向青少年群体，数据收集和使用必须遵守以下规范：

法律法规合规

  • 《个人信息保护法》(PIPL) — 未成年人个人信息需获得监护人同意
  • 《未成年人保护法》 — 网络保护专章，限制未成年人数据收集范围
  • 《数据安全法》 — 心理健康数据属于敏感个人信息，需加密存储
  • GDPR（如涉及海外用户） — Article 9 明确心理健康数据为特殊类别

数据安全措施

  • 所有训练数据必须脱敏处理 — 移除姓名、学校、联系方式等可识别信息
  • 使用项目已有的隐私保护层（privacy/sanitizer.py）进行自动脱敏
  • 模型训练使用差分隐私或联邦学习减少数据泄露风险
  • 数据集访问权限严格控制，仅算法团队成员可访问

推荐的安全数据获取渠道

渠道 优势 注意事项
公开学术数据集 已脱敏、合规、可立即使用 注意许可证（CC-BY / MIT / 学术用途限制）
平台用户数据（需授权） 最贴合目标域 需更新隐私政策、获取用户知情同意
合作医院/学校 临床数据质量高 需伦理委员会审批（IRB）
数据增强/合成 无伦理问题 使用 LLM 生成模拟青少年表达，扩充训练集
快速启动建议 建议从公开学术数据集入手（天池心理健康 + DASS-21 + CH-SIMS），这些数据集已经过伦理审查且可免费下载。在验证训练流程后，再逐步接入平台自有数据。所有公开数据集请检查其许可证是否允许商业/研究使用。
